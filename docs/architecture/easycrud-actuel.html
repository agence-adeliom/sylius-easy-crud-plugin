easy-crud — comment ça marche aujourd'hui

Architecture actuelle, basée sur l'ancienne pile Sylius (« legacy » : ResourceController + routage type: sylius.resource).

Classe Admin (ton code) Contrôleur CrudAdminFactory Grille Brique legacy Sylius

1. L'idée centrale : une seule classe pour tout

Quand tu crées un écran d'admin, tu écris une classe PostAdmin extends AbstractAdmin. Cette classe joue trois rôles à la fois :

1 · Type de formulaireElle hérite de AbstractFormType → AbstractResourceType. C'est elle que Symfony instancie comme form type.
2 · Définition de grilleElle implémente ResourceAwareGridInterface. Sylius Grid la reconnaît automatiquement comme une grille.
3 · Config des champs/UIconfigureFields(), configureActions(), configureFilters() décrivent l'écran (onglets, colonnes, champs).
La chaîne d'héritage : PostAdmin → AbstractAdmin → AbstractFormType → AbstractGridType → AbstractResourceType (Sylius). C'est pour ça qu'une seule classe peut être à la fois formulaire et grille.

4. Le chef d'orchestre : CrudAdminFactory

Service partagé, injecté dans chaque Admin. Il fait le lien entre le monde « Admin » et le monde « ressource Sylius » :

  • initContext($model) — cherche la ressource dans le paramètre sylius.resources par classe d'entité, et construit la Metadata + RequestConfiguration legacy. C'est ainsi que l'Admin sait « quelle ressource suis-je ».
  • Menu & colonnes — structure les onglets/colonnes du formulaire (Knp Menu).
  • Assets — accumule les CSS/JS/Webpack déclarés par les champs.
  • Outils — le Doctrine type guesser et le property accessor.
  • getViewVars() — produit les variables Twig (menu, colonnes, assets, thèmes de formulaire).

6. Le mécanisme $context

Un paramètre ?context=… est transmis à travers les routes et les options du formulaire. Deux usages :

  • Champs conditionnels : configureFields($pageName, $context) affiche des champs différents selon le contexte.
  • Actions custom ca: : ?context=ca:maMethode déclenche un appel dynamique à maMethodeAction() sur le contrôleur (dispatch dynamique).

7. Ce qui rend tout ça « legacy »

BriqueDépendance Sylius ancienne
ContrôleurSyliusCrudResourceController extends Sylius\Bundle\ResourceBundle\Controller\ResourceController legacy
Identité de la ressourceMetadata::fromAliasAndConfiguration() + paramètre sylius.resources legacy
Routestype: sylius.resource → ResourceLoader → ::xxxAction + défauts _sylius legacy
Requête couranteRequestConfiguration, resourcesCollectionProvider, findOr404 legacy
Grille & FormulaireResourceAwareGridInterface / AbstractResourceType — compatibles Sylius 2, ne changent pas
Le verrou principal. Tout le comportement « riche » d'easy-crud (le $context, les actions ca:, l'autocomplete, la construction du formulaire dans showAction) vit dans ce contrôleur legacy et s'appuie sur la Metadata legacy. C'est précisément ce qui doit être réécrit pour passer à la nouvelle mécanique Sylius 2 (voir le 2ᵉ document).
