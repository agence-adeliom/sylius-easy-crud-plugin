easy-crud — la structure cible en Sylius 2 natif

Comment l'architecture communiquerait si on abandonnait le contrôleur legacy au profit de la mécanique moderne : #[AsResource] + chaîne Provider → Processor → Responder.

Classe Admin (inchangée) main_controller (générique) Provider (je lis) Processor (j'écris) Responder / twigContext

1. Le changement de principe

Avant : chaque route → ton contrôleur, qui fait tout (lire, gérer le form, rendre).

Après : toutes les routes → un seul contrôleur générique (sylius.main_controller), qui orchestre une chaîne de petites briques spécialisées. Tu ne possèdes plus le contrôleur ; tu branches des briques dessus.

sylius.main_controllerle même pour toutes les opérations
→
Providerva chercher la donnée (liste ou objet)
→
Processorpersiste (create / update / delete)
→
Responderrend un template ou redirige

Plus un twigContextFactory par opération : il prépare les variables passées au template.

5. Ce qu'easy-crud devrait fournir (le vrai travail)

Un ProviderRéutiliser le Provider Doctrine par défaut pour le CRUD standard ; en écrire un custom seulement pour injecter la logique $context.
Un ProcessorLe Processor Doctrine par défaut suffit pour create/update/delete dans la plupart des cas.
Un twigContextFactoryLa pièce clé : reconstruire les variables que les templates easy-crud attendent (menu, colonnes, assets, icon/header) — aujourd'hui produites par CrudAdminFactory::getViewVars().

En résumé : la moitié « UI » d'easy-crud (Admin, champs, grille, formulaire) ne bouge presque pas. Tout l'effort se concentre sur le remplacement du contrôleur unique par les briques Provider/Processor/Responder, et sur la reconstruction des variables Twig via un twigContextFactory. Les cas délicats sont le $context et les actions ca: (dispatch dynamique → opérations explicites).
Stratégie recommandée : migration incrémentale, opération par opération (commencer par index), protégée par des tests fonctionnels figeant le comportement actuel, et en gardant la coexistence legacy/moderne pendant la transition.
